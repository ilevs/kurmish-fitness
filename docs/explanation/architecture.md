# Устройство приложения

## Почему всё работает без сети

Тренируются там, где связь плохая. Поэтому всё нужное лежит в приложении: каталог циклов, правила советов, разбор речи и дневник. Сеть нужна только для необязательной [синхронизации с Telegram](#почему-синхронизация-через-своего-бота), и без неё ничего не ломается. Синтез речи берётся у системы, а распознавание встроено в приложение.

Системное распознавание оказалось ненадёжным: на телефонах без сервисов Google вместо него открывается окно «Голосовой поиск недоступен». Поэтому распознавание встроено в приложение: движок sherpa-onnx и модель GigaAM v3 (CTC, int8, лицензия MIT). Для русской речи это одна из самых точных открытых моделей, а на современном телефоне фраза распознаётся за доли секунды. Первая версия на маленькой модели Vosk ошибалась слишком часто, от неё отказались.

Модель весит около 225 МБ, поэтому в APK её нет: при первой голосовой записи приложение один раз скачивает её в свои файлы (`VoiceModel`), сначала из релиза `voice-model` этого репозитория, а если он недоступен — с Hugging Face. Дальше распознавание работает без сети. Звук режет на фразы детектор речи Silero VAD (0,6 МБ, лежит в assets): фраза распознаётся целиком после короткой паузы и сразу дописывается в поле. Распознанные слова («сто двадцать на пять») превращает в числа тот же `TextNormalizer`, что и набранный текст. Нативные библиотеки собраны только для arm64: на 32-битных телефонах такая модель работала бы слишком медленно.

## Почему разбор текста, а не форма

Записывать тренировку удобнее одной фразой сразу после подхода, чем заполнять поля. Голос и текст проходят один и тот же разбор, а в поле видно, что именно распознано, и можно поправить руками. Разбор написан правилами, а не нейросетью: он предсказуем, мгновенный, весит килобайты и проверяется тестами.

## Слои

```
ui (Compose)  →  TrainerViewModel  →  core (чистый Kotlin)
                                        ├─ WorkoutParser   свободный текст → подходы
                                        ├─ Strength        оценка ПМ, проценты от ПМ
                                        ├─ WarmUp          таблицы подводящих подходов
                                        ├─ LoadCalculator  тоннаж, КПШ, интенсивность, время
                                        ├─ Programs        программы по микроциклам
                                        ├─ CycleCatalog    база циклов и подбор
                                        ├─ Coach           совет на сегодня
                                        ├─ TelegramSync    обмен с ботом Telegram
                                        └─ JournalStore    JSON-файл на устройстве
```

`core` не зависит от Android, поэтому всё, что решает «что и как тренировать», проверяется обычными модульными тестами. `ui` только показывает данные и передаёт действия.

## Почему JSON-файл, а не база данных

Дневник одного человека — это сотни записей в год. Один файл читается за миллисекунды, его легко понять и перенести, и не нужна генерация кода для базы.

## Почему синхронизация через своего бота

Своего сервера у приложения нет, и заводить его ради одного человека незачем. Бот Telegram — это готовый сервер, который хранит сообщения, пока их не заберут: приложение раз в несколько минут спрашивает у Bot API новые сообщения (`getUpdates`) и отправляет свои записи (`sendMessage`). Пока сети нет, ничего не теряется: записи приложения помечены как неотправленные, а сообщения ждут у Telegram.

Вход в личный аккаунт Telegram (чтобы писать в «Избранное») потребовал бы библиотеку TDLib на десятки мегабайт, ключи API и код подтверждения. Бот проще и безопаснее: токен даёт доступ только к чату с ботом.

Входящие сообщения разбирает тот же `WorkoutParser`, что и поле «Записать». Сообщения за один день собираются в одну запись, потому что в зале тренировку пишут по упражнению, а программа считает тренировкой каждую запись. Каждая часть записи хранит номер своего сообщения, поэтому исправленное в Telegram сообщение исправляет запись.

`TelegramSync` меняет данные только маленькими шагами через ту же функцию, что и экраны: пока идёт сеть, можно записать новую тренировку, и синхронизация её не затрёт.
